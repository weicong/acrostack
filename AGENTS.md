# AGENTS.md

## Architecture

ABP single-layer (app-nolayer) template: one C# project + one React SPA. No separate Domain/Application/Infrastructure layers. Multi-tenancy is enabled (`AcroStackModule.IsMultiTenant = true`).

- **`src/AcroStack/`** — ASP.NET Core host (API, auth, EF Core, entities, services, migrations). .NET 10, ABP 10.4, SQLite, OpenIddict auth.
- **`react/`** — React 19 SPA. Vite+ toolchain, TanStack Router/Query/Form, Fluent UI v9, Kubb codegen, OIDC auth.

## Backend Commands

```bash
dotnet build                              # Build solution
dotnet run --project src/AcroStack        # Run API (https://localhost:44320)
dotnet run --project src/AcroStack --migrate-database  # Run migrations + seed
pwsh migrate-database.ps1                 # Same, via script
```

EF Core migrations (run from repo root, project dir is `src/AcroStack`):
```bash
dotnet ef migrations add <Name> --project src/AcroStack --startup-project src/AcroStack
dotnet ef database update --project src/AcroStack --startup-project src/AcroStack
```

## Frontend Commands

Uses **Vite+** (`vp` CLI), not raw npm/pnpm scripts. Package manager is pnpm.

```bash
vp install          # Install deps (run after pulling)
vp dev              # Dev server (http://localhost:5173)
vp check --fix      # Format + lint + typecheck
vp test             # Run Vitest (watch mode)
vp test run         # Single Vitest run (no watch)
vp run generate-api # Kubb: regenerate API client from Swagger (backend must be running)
```

Backend must be running before `generate-api` — Kubb reads `http://localhost:5173/swagger/v1/swagger.json` (proxied).

## Key Conventions

- **Mapperly** (not AutoMapper) for object mapping. Mappers live in `src/AcroStack/ObjectMapping/`. Extend `MapperBase<TSource, TDest>` with `[Mapper(RequiredMappingStrategy = RequiredMappingStrategy.Target)]`. Register via `context.Services.AddMapperlyObjectMapper<AcroStackModule>()` in module.
- **Generic repositories** only — no custom repository interfaces (single-layer pattern). Use `IRepository<T, TKey>` directly.
- **Feature folders** in `src/AcroStack/Services/` and `src/AcroStack/Entities/` — group entity, DTOs, service together.
- **Auto API controllers** — ABP exposes app services as REST endpoints automatically. Only `HomeController` is hand-written.
- **`react/src/api/`** is auto-generated by Kubb. Do not manually edit; regenerate with `vp run generate-api`.
- **Path alias**: `@` → `./src` in the React app (configured in `vite.config.ts`).
- **SQLite** database (`AcroStack.db` in `src/AcroStack/`). Connection string in `appsettings.json`.
- **Swagger UI** available at `/swagger` when backend is running.

## Development Flow

1. Start backend: `dotnet run --project src/AcroStack`
2. In `react/`: `vp install && vp dev`
3. After changing backend API: `vp run generate-api` (from `react/`)
4. After adding/modifying an entity: add EF migration, then `dotnet run --project src/AcroStack --migrate-database`
5. Before committing: `vp check` and `vp test` in `react/`

## Testing

- Frontend: Vitest + Testing Library + jsdom. Setup at `react/src/test/setup.ts`. Tests colocated as `*.test.ts(x)`.
- Backend: no test project in this solution currently.
