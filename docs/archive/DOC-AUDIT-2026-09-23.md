## 2. 各文档核心信息归纳

- **根 `README.md`**：一句话定位（ABP 单层模板 + 自研 impersonation 替掉 Account Pro）→ 架构要点 → 模块一览 → 快速开始 → 文档结构 → 生产部署 → 相关资源。信息密度最高，也是唯一写"生产部署/证书"的地方。
- **根 `AGENTS.md`**：架构（含 UoW 事务禁用原因、`AcroStack.Common` 已删除的历史说明）→ 后端命令 → 前端命令 → Key Conventions（Mapperly / 仓储 / Feature 目录 / 自动 API / 显式事务 / 生成物 / `lib/` 准入）→ 开发流 → 文档规则 → 测试 → Reference。
- **`.agents/agents.md`**：根 AGENTS.md 的压缩版（架构 2 行、命令 2 块、约定 7 条）+ Skills 索引表。
- **`modules/.../README.md`**：写得很克制——对应哪个 Pro 能力、明确列出"不做什么"、4 个关键设计决策（含已废弃方案及原因）、依赖边界。是"决策型文档"的样板。
- **`react/README.md` / `react/AGENTS.md`**：工作区结构树、6 条 `vp` 命令、Vite+ Monorepo 三条硬约束（包级 lint 不生效、`defaultPackage` 语义、`catalog:` 版本锁定）。
- **`apps/web/README.md`**：技术栈表、目录树、脚本表、generate-api 两法、环境变量表、认证链路、Docker。
- **`apps/web/AGENTS.md`**：源码布局 + **`lib/` 准入规则** + 样式禁令的"应用层摘要版"。
- **`packages/core/AGENTS.md`**：子路径 × 职责 × 关键导出 的表格 + **依赖倒置三条铁律**（不读 env、不 import api-client、不碰路由）+ 与 ABP 官方文档的对应关系 + 已知行为差异。质量最高的一份。
- **`packages/ui/AGENTS.md`**：域 × API × 第三方依赖表 + 域间零依赖 + **样式所有权 R1–R5**。
- **`packages/api-client/AGENTS.md`**：生成物/手写文件的边界划分 + 生成规程 + 版本升级流程 + 一个真实的已知环境问题（safe-delete 与 dev server 冲突）。

## 4. 过时 / 与代码不符（O1–O12，均为已核对的硬事实）

- **O1** 根 README L22「前端 `react/apps/web/src/api/` 由 Kubb 从 Swagger 生成」——**该目录不存在**，已迁至 `react/packages/api-client`。
- **O2** `apps/web/Dockerfile` 硬伤：`COPY react/packages/app-shell/package.json` —— **无 `app-shell` 包**（现为 `api-client` / `core` / `ui`），`pnpm install --frozen-lockfile` 会失败。同段 README 另有三处不符：说镜像 `node:20-alpine`（实际 `node:22-alpine`）、说 `pnpm run build` 内部是 `vp check && vp build`（实际根脚本为 `vp -C apps/web build`）、说"在 `react/` 目录构建"（Dockerfile 注释声明构建上下文是仓库根）。
- **O3** 根 AGENTS.md「Testing: No frontend tests currently」——**已有 3 个测试文件**（`packages/ui` 下 `AppShell.test.tsx`、`useDataTable.test.ts`、`field-error.test.ts`），与 `react/README.md`、`react/AGENTS.md` 的"`vp test`"表述冲突。
- **O4** Mapper 目录三处矛盾：根 AGENTS.md 说 mappers 在各模块 `ObjectMapping/`；`.agents/agents.md` 说在 `main/AcroStack/ObjectMapping/`；**实际两处都不存在**（`main/AcroStack/` 无该目录，`modules/AcroStack.Impersonation/` 也无）。真实目录是 `Dtos/ EfCore/ Entities/ Handlers/ Localization/ Options/ Permissions/ Services/`（多了 `EfCore`/`Handlers`/`Options`，少 `ObjectMapping`）。
- **O5** 根 AGENTS.md 声明 ADR 存放于 `docs/adr/`——**该目录不存在**（`docs/` 下只有 `archive/`）。
- **O6** Node 版本三说：根 README「Node 18/20」、Dockerfile `node:22-alpine`、`devEngines` 锁 pnpm 11.8.0。
- **O7** `.agents/skills/abp-single-layer-template/skill.md` 的示例结构为 `AcroStack/src/AcroStack/{Data,Entities,Services,react}` —— 与本仓库 `main/AcroStack` + `modules/<Feature>` 的实际布局不符。
- **O8** `.agents/skills/agnes-ai-multimodal/skill.md`（505 行）讲 Agnes AI 图像/视频生成，**与本仓库毫无关系**，却被 `.agents/agents.md` 的 Skills Index 正式列出——会误导 Agent 去调用不存在的集成。
- **O9** 归档 `HANDOFF-P0P1P2.md` 的"已完成"记录与现状冲突：它称已新建 `modules/AcroStack.Common/`（含 `IAcroStackTransactionExecutor`），而根 AGENTS.md 说该模块**已被删除**；文中反复出现的 `AcroStack.AccountPro` / `AuditLogging` / `OpenIddictManagement` / `Chat` 四个模块现在都不存在。另外文内命令仍用 `npm run generate-api`、`npx vp lint`，与现行 `vp` 工作流不符。虽有"已归档"横幅，但横幅只说"任务已完成"，没说"文中模块已被删除"，读档极易被误导。
- **O10** `apps/web/README.md` 技术栈表把 TanStack Form、Axios、oidc-client-ts 列为应用级技术，实际分别属于 `packages/ui`、`packages/core`（`apps/web/package.json` 中并无这三项）。
- **O11** 根 README「架构」与根 AGENTS.md「Architecture」描述前端时都只提 `apps/web`、`packages/ui`、`packages/api-client`，**漏掉 `packages/core`**；而 `react/README.md`、`react/AGENTS.md` 都把它作为核心包描述。
- **O12** 根 AGENTS.md「Documentation」的 Evergreen 清单未纳入 3 份 `react/packages/*/AGENTS.md`——它们实质上是维护最勤、信息最密的常青文档，却不在维护规则覆盖范围内。

## 5. 表述不一致（C1–C7）

- **C1 语言割裂**：根 `AGENTS.md` 全英文、根 `README.md` 中文、`apps/web/AGENTS.md` 中英混排（同一条目内中英句子交替）。同一条规则存在两套语域。
- **C2 命令执行位置**：`react/AGENTS.md` 明确"不要进入包目录再敲全局命令"，而 `apps/web/README.md`「快速开始」直接在应用语境下写 `vp install / vp dev`，`api-client/AGENTS.md` 又给出 `vp -C packages/api-client ...`。三者都对，但缺少统一表述（"根执行；`-C` 是对包定向"）。
- **C3 多租户口径**：README 说多租户关闭；`packages/core/AGENTS.md` 完整描述 `tenant` 子路径与 `__tenant` 头，`apps/web/README.md` 也提 `__tenant`。没有任何文档解释"已关闭但前端仍保留该能力"的原因。
- **C4 模块表口径**：根 README「模块一览」把框架自带能力（Audit Logging / Background Jobs / BLOB Storing）与自研模块混在同一张"模块"表，且表下文字"各模块详情见 `modules/<模块名>/README.md`"指向大量不存在的文件（实际只有 1 份）。
- **C5 `vp dev` 解析机制**：`react/README.md` 说是 `defaultPackage` 生效，而工作区根 `package.json` 实际用 `vp -C apps/web dev` 脚本实现。两种机制并存、说法不一。
- **C6 目录树根结点**：`apps/web/README.md` 的目录树根写 `react/`（应为 `apps/web/`），且未体现 `packages/` 视角，与 `react/README.md` 的树无法拼合。
- **C7 冲突仲裁**：只有 `apps/web/README.md` L39 一处声明"与 README 冲突时以 AGENTS.md 为准"，其余文档之间没有优先级约定。

## 6. 改进建议

### 6.1 建立单一事实源（SSOT）与优先级（治本）

```
L0  根 AGENTS.md          —— 跨栈约定唯一权威（架构边界、命令、编码规范、文档规则）
L1  各域 AGENTS.md        —— 域内唯一权威（react/ 、apps/web/、packages/*/）
L2  README（各级）        —— 只做"定位 + 快速开始 + 导航"，细节一律链接到 L0/L1
L3  .agents/              —— 只读镜像，须声明"由 L0 派生，冲突以 L0 为准"
```

配套动作：每份文档开头加 4 行元信息块（作用域 / 权威级别 / 上游文档 / 冲突时以谁为准），把 C7 从"一处约定"变成"全局约定"。

### 6.2 按建议立刻修的硬伤（有明确正确答案，不需讨论）

1. `apps/web/Dockerfile`：`packages/app-shell` → 三个真实包；同步 README 的 Node 版本、`build` 脚本、构建上下文三处描述（O2、O6）。
2. 根 README L22 → 改为 `react/packages/api-client`（O1）。
3. 根 AGENTS.md 的 Mapper 目录表述 → 改成实际目录，并从"约定"降级为"现状"（O4）；同步 `.agents/agents.md`。
4. 根 AGENTS.md 测试章节 → 改为"`packages/ui` 下有 3 个 Vitest 用例，用 `vp test`"（O3）。
5. 根 AGENTS.md 的 `docs/adr/` → 要么建目录（把 O9 里的 §5 踩坑提炼成 2~3 份 ADR），要么删掉这条声明（O5）。
6. 架构描述三处补上 `packages/core`（O11）；Documentation 清单补 3 份 packages AGENTS.md（O12）。
7. 删 `.agents/skills/agnes-ai-multimodal`，并从 Skills Index 移除（O8）；更新 `abp-single-layer-template` 的结构示例（O7）。
8. 归档 HANDOFF 顶部横幅补一句"文中提到的 AccountPro/AuditLogging/OpenIddictManagement/Chat/Common 五个模块现已删除，仅 §5 技术决策仍有参考价值"（O9）。

### 6.3 消除重复的具体做法

- **命令表只留一份**：建议放在根 AGENTS.md，其余文档改为"命令见根 AGENTS.md"的一行链接 + 本域特有命令补充（如 `api-client` 的 `generate`）。
- **文档索引只留一份**：根 README「文档结构」保留（面向人），根 AGENTS.md「Reference」删除（面向 Agent 的改为指向 README）。
- **样式禁令只留权威版**：`apps/web/AGENTS.md` 的摘要压缩成 3 行 + 指向 `packages/ui/AGENTS.md` 的链接，避免双份维护（D6）。
- **D1 架构总览**：README 保留"一图 + 5 条要点"，AGENTS.md 改为"边界与约束"（事务、模块归属、样式所有权这类"不能做什么"），`.agents/agents.md` 直接引用，不再复述。

### 6.4 表述层面的改进

- **统一语言**：建议 AGENTS 系列统一英文（面向工具、便于跨项目复用），README 系列统一中文（面向人），`apps/web/AGENTS.md` 的混排逐条归一化。
- **补"为什么"**：C3（多租户关闭但保留前端能力）、O4 之类"现状与直觉不符"的地方，补一句原因，否则下一个人会当成 bug 修掉。
- **README 模块表拆分**：拆成"框架自带能力（无独立 README）"和"自研模块（有 README）"两组，并删掉指向不存在文件的通配说明（C4）。
- **目录树统一根结点**：`apps/web/README.md` 的树改为 `apps/web/`，并与 `react/README.md` 的树在层级上可直接拼合（C6）。

### 6.5 防回归（让文档不再腐烂）

- 在 CI（或 `vp check` 之外加一条 `vp run check-docs`）里加一个轻量巡检脚本：grep 文档中出现的路径常量（如 `packages/app-shell`、`src/api`、`docs/adr`、`ObjectMapping`）是否仍存在，以及 README/AGENTS 中的命令字符串是否与 `package.json` scripts 一致。O1/O2/O5 这类问题本可以被一条 grep 拦住。
- 把"改了架构/命令/包结构必须同步哪些文档"写成根 AGENTS.md 里的一条显式 checklist（现在只有"新增模块要更新 README"一条）。
