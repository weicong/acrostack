### 审计发现的问题（按严重度）
P0:
1. `main/AcroStack/appsettings.json:90` 明文 TokenSigningKey 已入库，且**无启动 fail-fast 校验**
   （对比 openiddict.pfx 已有校验）。部署遗漏即等于可伪造学员/投屏令牌。
2. `ConversationAppService.cs:428-431` 删除消息两次 DeleteAsync 无事务包裹（同文件 SendMessage 有）。
3. `FileManagementAppService` 全部多步写无事务，靠 try/catch 手写补偿；
   崩溃发生在 blob 保存后、catch 前会留孤儿 Blob。涉及上传(240-280)/新版本(374-395)/还原(625-652)。

P1:
4. `AddAlwaysDisableUnitOfWorkTransaction()` + `TransactionBehavior=Disabled` 属症状治疗：
   正确性责任从框架转嫁给开发者记忆，classroom 与 Chat 各写各的事务封装，FileManagement 已漏。
   建议：先抽宿主级统一 `IAcroStackTransactionExecutor`，再评估恢复 Auto。
5. SQLite WAL 未在代码中配置。当前 AcroStack.db 头部 write/read version=2（WAL），
   但这是 DB 文件持久属性，删库重建/CI/Docker 会退化到 rollback journal → 读写互斥。
   全仓无 `PRAGMA journal_mode`。另 -wal 已 4.1MB 未主动 checkpoint。
6. `ClassroomStatisticsService.cs:156-158` 教师题目记录接口 N+1：
   `foreach (var sq in sessionQuestions) await _questionRepository.GetAsync(sq.QuestionId)`。
   由提交 a6a9c97 引入。

P2:
7. `ClassroomConsts.MaxSubmitsPerMinute` 全仓仅 1 处定义、0 处使用（僵尸常量）。
8. 后端仅 Classroom.Tests 两个文件；前端无测试框架，但 README 写着 `vp test run`（跑不通）。
9. 文档漂移 4 处：`react/AGENTS.md` 的 `lib/classroom/studentSession.ts`（已不存在）；
   classroom README 中 e2e/压测脚本路径写的是仓库根（实际在 `etc/scripts/`）；
   根 AGENTS.md 漏了手写的 `AcroStack.Chat/Controllers/ChatController.cs`；

### 架构观察（尚未动手）
