## 任务：按 docs/requirements.md 搭 TanStack Router + shadcn/ui 脚手架

### 调研结论（关键技术事实，已实测）

**1. shadcn `--monorepo` 没有 TanStack Router 模板**
`shadcn init --monorepo` 只支持 5 个模板：`next` / `vite` / `react-router` / `start`(TanStack **Start**) / `astro`。
纯 router-only 的 TanStack Router **不存在**对应模板 → monorepo 骨架必须手工搭，
或改用 `shadcn init --template vite --monorepo`（拿到的 apps/web 是纯 Vite 裸 React 应用）。

**2. Vite+ 的 `vp create` 也没有 TanStack Router 模板**
`vp create --list` 内置只有 4 个：`vite:monorepo` / `vite:application` / `vite:library` / `vite:generator`；
简写社区模板：`vite`、`@tanstack/start`、`next-app`、`nuxt`、`react-router`、`svelte`、`vue`。
→ TanStack Start 模板不能用（需求明确 router-only）。

**3. TanStack 官方 CLI 已换代**
`create-tsrouter-app` **已废弃**，提示改用 `tanstack create --router-only`
（即 `npx @tanstack/cli@latest create`）。加 `--router-only` 后 Start 相关 add-on/部署适配器**全部禁用**，
连 `--add-ons shadcn` 都会被忽略（实测打印 "Ignoring --add-ons in router-only compatibility mode"）。
→ 所以 shadcn 只能自己接。

**4. router-only 骨架实测产物**（`tanstack create --router-only --no-install --no-toolchain --no-git --blank`）
```
index.html            # <div id="app"> 挂载点（不是 #root！）
src/main.tsx          # createRouter + RouterProvider
src/router.tsx        # getRouter()（Start 风格遗留下来的，SPA 下与 main.tsx 二选一）
src/routes/__root.tsx
src/routes/index.tsx
src/styles.css
vite.config.ts        # defineConfig from 'vite'；resolve.tsconfigPaths: true；tanstackRouter({target:'react', autoCodeSplitting:true})
tsconfig.json         # paths: {"#/*": "./src/*", "@/*": "./src/*"}
tsr.config.json       # { "target": "react" }
```
关键点：`resolve.tsconfigPaths: true` 是 Vite 8 新特性，**不需要 @types/node + path.resolve**。
依赖版本：react 19.2、vite 8、typescript 6.0.2、@vitejs/plugin-react 6、@tanstack/router-plugin、@tanstack/router-cli。
`package.json#imports` 用 `"#/*": "./src/*"`。

**5. shadcn 样式命名规范（实测）**
- registry 路径必须带 base 前缀：`/r/styles/{radix|base|aria}-{vega|nova|maia|lyra|mira|luma|sera|rhea}/{item}.json`
- 裸 `nova` / `vega` → 404。所以需求里说的 `Nova` → 实际落地值 **`base-nova`**（对应 Base UI）。
- Nova = 更紧的 padding / 更小的圆角，适合 dashboard / 数据密集型界面。
- shadcn `init -b/--base` 可选 `base|radix|aria`；`-p/--preset` 选风格。

**6. shadcn monorepo 约定**
- 目录：`apps/web`（应用）+ `packages/ui`（组件），构建系统官方给 Turborepo（**可换成 Vite+**）。
- 两个 workspace **各自都要有 components.json**，且 `style` / `iconLibrary` / `baseColor` 三项必须一致。
- Tailwind v4 下 `tailwind.config` 留空 `""`。
- 别名：app 侧 `ui`/`utils` 指向 `@workspace/ui/...`；ui 包用 `@workspace/ui/...` 自身别名。
- 共享包 `packages/ui` 需要 `exports` 暴露 `./globals.css`、`./components/*`、`./lib/*`、`./hooks/*`。

**7. Base UI 的 API 差异（重要，抄 new-york/Radix 版代码会踩坑）**
- 复合组件用 `render={<Comp />}` 属性，**不是** Radix 的 `asChild`。
- 数据属性是扁平的：`data-open` / `data-vertical`（Radix 是 `data-state=open` / `data-orientation=vertical`）。
- 图标不再直接用 lucide 组件，registry 里用 `IconPlaceholder`（多图标库可切换）。
- `Collapsible` 用 `render={<SidebarMenuItem />}`；`default-open` 对应 CSS 是 `group-data-open/collapsible:`。

**8. 参考布局 sidebar-07 的真实结构**
`SidebarProvider > AppSidebar + SidebarInset`
AppSidebar = `Sidebar collapsible="icon"` → SidebarHeader(TeamSwitcher) / SidebarContent(NavMain + NavProjects) / SidebarFooter(NavUser) / SidebarRail。
头部 header 高 `h-16`，折叠态 `group-has-data-[collapsible=icon]/sidebar-wrapper:h-12`。
breadcrumb 在 header 左侧，前置 SidebarTrigger + Separator(vertical|h-4)。

### 踩到并修掉的 4 个真 bug（都已浏览器实测复验）

**1. Tailwind v4 在 monorepo 里扫不到 apps/web（最坑，查了很久）**
症状：侧边栏整体塌成 0 宽 0 高，`getComputedStyle` 显示 `display:none`，但 class 里明明有 `md:flex`。
根因：Tailwind v4 按 **CSS 文件所在目录**探测源码 → `packages/ui/src/styles/globals.css`
只扫 `packages/ui`，`apps/web` 用到的类（`md:flex` 等）根本没生成。
修法：`globals.css` 里加 `@source "../../../.."` + `@source "../../src"`。
验证：`curl localhost:5173/@fs/.../globals.css | grep -c 'md\\:flex'`。
**教训**：写脚本遍历 `document.styleSheets` 找规则必须递归 `@layer`/`@media` 的 `cssRules`，
否则会得到「0 条规则」的假象，把人带偏。

**2. 面包屑少一级**：`navItemsByPath` 只索引了顶层项，没索引 `children`，
所以 `/posts/new` 查到的是父节点「文章」，链断在「首页 > 文章」。
修法：构建 map 时把 `item.children` 也放进去。

**3. Collapsible open 态高度为 0**：Base UI 的 Panel 通过 `--collapsible-panel-height`
暴露高度，但 open 态没有现成高度规则（shadcn 只给了动画 keyframes），`height:auto` 撑不开。
修法：在 globals.css utilities 层补 open/closed 两条规则。

**4. 侧边栏折叠状态刷新即丢**：上游 `SidebarProvider` 只**写** `sidebar_state` cookie，
Next.js 由服务端读回；纯 SPA 没服务端 → 必须自己在 `__root.tsx` 里读回并传给
`defaultOpen={readSidebarOpen()}`。

### 其它 Base UI 与 Radix 的差异（记牢，否则抄示例必错）
- 用 `render={<Comp />}` 而不是 `asChild`
- 数据属性扁平：`data-open` / `data-vertical`（Radix 是 `data-state=open` / `data-orientation`）
- Tailwind 对应 `data-open:` / `group-data-open/`
- `render={<SidebarMenuItem />}` 会把 `data-slot` 覆盖到那个 li 上，
  按 `data-slot=collapsible` 找节点会漏，改用 `li.group\/collapsible`

### 一个折腾很久的「假 bug」——记牢，别再踩
排查侧边栏子菜单高度时，一度以为 CSS 没生效：`--collapsible-panel-height` 是 `auto`、
`animation-name: none`、子 `<ul>` 量到 0 高。**真相是那根本没问题**——
`<ul>` 带 `group-data-[collapsible=icon]:hidden`，而当时侧边栏正处于**持久化的折叠图标态**
（cookie `sidebar_state=false`），子菜单本就该隐藏。
展开后立刻量到 **64px**（两行 × 28px + padding），一切正常。
**教训**：在浏览器里量尺寸前，先确认组件的**状态**（`data-state` / `data-collapsible`），
否则会把「设计使然的隐藏」误判成「样式失效」。
顺带确认：`render={<SidebarMenuItem />}` 会把 `data-slot` 从 `collapsible` 覆盖成
`sidebar-menu-item`，所以按 `data-slot=collapsible-content` 查节点查不到——
面板要靠 `trigger[aria-controls]` 反查 id。
