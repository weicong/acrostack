## 用官方 `migrate-radix-to-base` skill 做 Radix UI → Base UI 迁移（whole-project）

**结果**：14 个 wrapper + `use-mobile` 全部换成 base-nova 变体，`components.json` 两个文件
`radix-nova` → `base-nova`，`radix-ui@1.6.7` 出、`@base-ui/react@1.8.0` 入（lockfile 里 radix 出现 0 次）。
`tsc` 双包干净、`vp build` 绿、浏览器冒烟全过。**0 wrappers remain on Radix。**
报告写在 `.migration/`（14 个组件各一份 + `project.md`，按 skill 规定的结构）。

**策略**：skill 的「golden pair」路线。**CLI 用不了** —— 沙箱里
`pnpm dlx shadcn@latest …` 报 EPERM（读 pnpm dlx 缓存被拦），所以改用 skill 也认可的
「按 URL 取 base 变体」形式：`/r/styles/base-nova/<c>.json`，再用与上次相同的导入归一化脚本写入。

**分类步骤（skill 第 1 步）**：把每个 wrapper 同时与「声明 style = radix-nova」和
「实际来源 = new-york-v4」比对。与 new-york-v4 的差异**只有 oxfmt 的尾逗号/箭头函数括号**
（用空白无关指纹 + SequenceMatcher 逐字符定位确认），即 **14 个 wrapper 全是 pristine、
零用户定制** → 可以整份替换，不需要三方合并。与 radix-nova 差异很大，因为两代 registry 不是同一份代码。

**消费方改动**（app 代码，skill 说「没有 CLI 机制，必须手改」）

- `asChild` → `render`，**17 处**（nav-main 4 / nav-user / team-switcher / theme-toggle /
  breadcrumb.tsx / posts 三个路由页）。
- **`nativeButton={false}` 7 处**（`Button` 的 render 目标是 `<a>`）。
  ⚠️ 这条**不在 skill 的 `consumer-props.md` 里**（已在其报告里记为 gap），
  规则在 `shadcn` skill 的 `rules/base-vs-radix.md`。不加会打 console error。
  实测只有 `@base-ui/react/button` 读 `nativeButton`（`Button.mjs:18`），`useRender` 完全不认 →
  `SidebarMenuButton render={<Link/>}` 不会报警告。
- **`DropdownMenuLabel` 必须搬回 `DropdownMenuGroup` 内**（team-switcher / nav-user）——
  `Menu.GroupLabel` 读 `MenuGroupContext`，否则点开菜单就抛（这就是 9-25 修过的那个 bug）。
- 类名改写：`data-[state=open]:` → **`data-popup-open:`**（菜单触发器专用！实测
  `MenuTriggerDataAttributes` 只输出 `data-popup-open`/`data-pressed`/`data-disabled`，
  **没有 `data-open`**；`data-open` 是 Collapsible 那类用的）、
  `group-data-[state=open]/collapsible:` → `group-data-open/collapsible:`、
  `data-[orientation=vertical]:` → `data-vertical:`、`w-(--radix-dropdown-menu-trigger-width)` → `w-(--anchor-width)`。
- Avatar 的 `h-8 w-8 rounded-lg` 覆盖被**去掉**（base-nova 的 Avatar 是 `rounded-full` +
  圆形 `after:` 环，只改 root 会留下圆环套方块的怪样子）。

**其他**：`globals.css` 重新加回 `.cn-rtl-flip` 和 Base UI 的 Collapsible 面板高度补丁
（`[data-slot=collapsible-content][data-open|data-closed]`，radix 那轮删掉的），两者都确认进了构建产物。
文案同步回 base-nova（README / docs/requirements.md / 首页 stats / about / 种子文章）。

**验证**：`data-active` 是**存在性属性**（`data-active=""`，不是 `"true"`）+ `aria-current="page"`——
第一遍我用 `=== "true"` 判断，误以为高亮坏了。浏览器实测：菜单能开（team switcher 4 项、nav-user、
主题菜单）、`data-popup-open` 与 `--sidebar-accent` 背景都出现、删除弹窗能开、`render` 链接能跳
（`/posts` → `/posts/new`）、面包屑 `首页 > 文章 > 新建`、控制台无应用报错（只有扩展噪音 + favicon 404）。
