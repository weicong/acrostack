### 关键结论

**两个项目已经是同一套底座** —— Vite+ / pnpm workspace / TanStack Router 文件式路由 /
React 19 / TS 7 / oxlint+oxfmt。所以不是"换技术栈"，真实差异只有三处：

1. **UI 库**：Fluent UI v9 + Griffel → shadcn/ui `base-nova`（**Base UI 1.8.0，非 Radix**）+ Tailwind v4

**用户指示**：「执行吧，不要遗留历史包袱」。报告归档在 `docs/archive/frontend-shadcn-basemono-migration-feasibility.md`。

### 最终架构

```
react/
├── apps/web/src/{routes, shell, pages, lib, components}
└── packages/{core, ui, layout, api-client}
```

- `packages/ui` 换成 **shadcn base-nova 原语**（`components/*` 30 个 + `hooks` + `lib` + `globals.css`）
  + 保留 `data-table`/`dialog`/`form` 三个业务无关机制封装
- **新增 `packages/layout`**（`@acrostack/layout`）：路由无关的 AppShell / 侧栏 / 面包屑 / `PageHeader` / `useTheme`
- **删除**：`@acrostack/ui/{layout,theme,app-shell}` 三个域、`apps/web/src/components/layout/*`、
  `lib/routing/*`（route-config / shell-menu / router）、`usePageTitle` / `useMediaQuery`
- **新增 `apps/web/src/shell/`**：`route-meta.ts`（staticData → 菜单/面包屑）、`layout.tsx`、

### 测试抓到的真实回归（值得记）

`route-meta.ts` 重写时丢了「**子项全被权限过滤 → 父项也消失**」这条规则，
导致无权用户会看到一个点进去必然 403 的空父菜单。原 `shell-menu.ts` 有这条，我漏了。
修法：**先不过滤地还原父子结构**，再算可见集合，最后删掉「有 nav 子项但无可见子项」的父项。
→ 教训：迁移这类「把配置式菜单改成路由树推导」的逻辑时，**必须把旧实现的每条过滤规则逐条对一遍**。

### 环境踩坑

- **ABP 后端跑不起来**：`wwwroot/libs` 缺失 → 所有请求 500。
  修法 `cd main/AcroStack && abp install-libs`（该目录被 gitignore，本来就要生成）。
  用环境变量 `AbpMvcLibs__CheckLibs=false` **无效**——ABP 是在代码里 `Configure<>` 的，不读配置。
- **OIDC 回调地址有两个来源，运行时配置优先**：`dynamic-env.json` 的 `oAuthConfig.redirectUri`
  **压过** `.env.development` 的 `VITE_APP_URL`（见 `packages/core/src/config/runtime-config.ts:152`）。
  所以改 dev 端口后要同时改 `dynamic-env.json`（`baseUrl` + `redirectUri`）并重播种 DB。
  另：`.env.development.local` 在这次 Vite+ 里**没生效**，最后是直接改 `.env.development` 再 `git checkout` 还原。
- 5173/5174/5175 被其它项目的 dev server 占着 → 本项目 dev 落到 **5176**。
- `vp check --fix` 与 `vp build` 串在同一条命令里跑过一次偶发构建失败（重跑即好），
  疑似 `check --fix` 改文件与构建读文件竞争。
